# keyset-kit

Tiny, type-safe keyset (cursor) pagination for Prisma, TypeORM, Mongoose and Express. Zero runtime dependencies.

## Why

`OFFSET` pagination gets slower the deeper you page, because the database still reads and throws
away every skipped row. It also returns duplicates or skips rows when data changes between
requests. Keyset pagination fixes both by continuing from the last row you saw, but getting
multi-column sorts, ties, nulls and tamper-proof cursors right is fiddly. `keyset-kit` handles
all of that in a few lines of code.

## Features

- **Correct under change**: no duplicates or skipped rows when data is inserted between requests.
- **Multi-column sorts** with per-field direction, ties broken by a unique field.
- **Null-aware ordering** (`nulls: 'first' | 'last'`), with PostgreSQL defaults.
- **Typed cursors**: Dates, bigints and decimals survive the round trip.
- **Tamper-proof cursors** (optional HMAC-SHA256 signing) that can't be reused under a different sort.
- **Forward and backward** pagination; `limit + 1` fetch, no count query.
- **Zero runtime dependencies**, fully typed: sort fields are checked against your model.

## Quick start

<!-- prettier-ignore -->
```ts
import { keysetParams, setLinkHeader } from 'keyset-kit/express';
import { paginatePrisma } from 'keyset-kit/prisma';

app.get('/posts', keysetParams<Post>({
  allowedSort: ['createdAt', 'title'],
  defaultSort: [{ field: 'createdAt', direction: 'desc' }, { field: 'id', direction: 'asc' }],
  secret: process.env.CURSOR_SECRET, // optional: sign cursors
}), async (req, res) => {
  const page = await paginatePrisma(prisma.post, { where: { published: true } }, req.keyset);
  setLinkHeader(res, req, page.pageInfo); // Link: <...?after=...>; rel="next"
  res.json(page); // { data, pageInfo: { hasNextPage, endCursor, ... } }
});
```

Clients page with `?after=<endCursor>` (or follow the `Link` header) and may pass
`?limit=` and `?sort=-createdAt,title`. Invalid input gets a 400 Problem Details response. The
last `defaultSort` field (`id`) is the unique tie-breaker, appended to every sort.

## Database notes

- **Null ordering.** By default nulls sort like PostgreSQL: last ascending, first descending.
  Set `nulls: 'first' | 'last'` per field to change that (Prisma and TypeORM emit `NULLS FIRST/LAST`).
  MongoDB can't change its null order: null and missing fields always come first ascending and
  last descending. The Mongoose adapter follows that order and rejects a contradicting `nulls` option.
- **Timestamp precision.** Cursors carry JavaScript `Date`s (milliseconds). Use `timestamp(3)`
  columns in PostgreSQL (Prisma's default for `DateTime`), or rows that differ by microseconds can
  be skipped or repeated.
- **One type per sort field in MongoDB.** Range operators only match values of the same BSON
  type, so a sort field shouldn't mix, say, numbers and strings.

## Development

Supports Node ≥ 22. Development uses Node 24 LTS (pinned in `.node-version`; [fnm](https://github.com/Schniz/fnm) picks it up automatically) and pnpm via Corepack (`corepack enable`; Corepack ships with Node 22 and 24).

```sh
pnpm install
pnpm generate        # Prisma clients for the tests and the example
pnpm build           # tsup → dist/ (the examples import the built package, so build before lint)
pnpm lint            # ESLint + (pnpm format:check for Prettier)
pnpm typecheck
pnpm test            # unit + type tests
pnpm test:int        # integration tests on real databases (requires Docker)
pnpm test:coverage   # both, with coverage thresholds (requires Docker)
pnpm test:examples   # smoke-test the example apps (requires Docker; run pnpm build first)
pnpm docs:dev        # docs site with API reference at http://localhost:5173
pnpm check:package   # publint + are-the-types-wrong
pnpm size            # size-limit (core ≤ 3 kB min+gzip)
pnpm bench           # OFFSET vs keyset on 1M PostgreSQL rows; rewrites bench/RESULTS.md (Docker)
```
